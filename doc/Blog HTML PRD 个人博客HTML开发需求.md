## 15. 验收标准

推荐使用 Given / When / Then。

### AC-001 创建功能

**Given**

用户已经登录，并拥有创建权限。

**When**

用户输入合法内容并点击“创建”。

**Then**

1. 系统成功创建数据
2. 页面进入成功状态
3. 用户可以查看新创建内容
4. 数据正确保存
5. 对应埋点成功上报

### AC-002 输入错误

**Given**

用户正在填写表单。

**When**

用户输入非法内容。

**Then**

1. 不允许提交
2. 错误字段显示明确提示
3. 用户已填写的其他内容不丢失

# PRD 自检清单

提交评审前建议检查：

- [ ] 是否说明为什么要做？
- [ ] 是否定义了明确的用户问题？
- [ ] 是否定义目标与成功指标？
- [ ] 是否明确本期范围和非目标？
- [ ] 是否覆盖核心用户场景？
- [ ] 主流程是否完整？
- [ ] 功能逻辑是否足够明确？
- [ ] 是否写清业务规则？
- [ ] 是否考虑异常情况？
- [ ] 是否定义 Loading / Empty / Error 状态？
- [ ] 是否定义权限？
- [ ] 是否定义数据与埋点？
- [ ] 是否有明确验收标准？
- [ ] 是否说明依赖与风险？
- [ ] 是否有上线和回滚方案？
- [ ] 产品、设计、开发、测试是否可以仅依赖 PRD 和关联文档理解需求？

---

> 一个好的 PRD 不追求“写得多”，而追求：关键决策有依据、需求边界明确、逻辑无歧义、异常有处理、最终可验收。
